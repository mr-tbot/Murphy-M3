First-day results: **freeink-reader (full EPUB engine) runs on TBOT's Murphy M3 with display,
buttons, frontlight, and — new capability — a working microSD over 4-bit SDMMC.**

## What was done

1. **Stock firmware safety net**: full 16 MB dump + SHA256, partitions extracted, eFuses
   verified clean (no secure boot / flash encryption). Restore is one esptool command.
2. **freeink-sdk SDMMC fix** (branch `m3-tbot` in [upstream/freeink-sdk/](../upstream/freeink-sdk/)):
   the `MurphyM3` profile had a wrong SPI pin guess + `NO_SDMMC`, so SD never worked. Rewired to
   the real 4-bit SDMMC bus (CLK=16 CMD=17 D0=15 D1=14 D2=21 D3=18, `busWidth` 4) with
   `powerEnable=GPIO10` **active-LOW** — the SDK's existing pulse-HIGH-hold-LOW mount sequence
   matches that AO3401 gate exactly. `FREEINK_SD_SDMMC` now auto-enables for MURPHY.
   **Verified on hardware: 32 GB card mounts reliably.** PR-worthy upstream.
3. **freeink-reader `[env:murphy]`** (local, [upstream/freeink-reader/platformio.local.ini](../upstream/freeink-reader/platformio.local.ini)):
   mirrors the sticky env with `-DFREEINK_DEVICE_MURPHY=1` + `-DUSE_BLOCK_DEVICE_INTERFACE=1`,
   built against the sibling SDK working copy. Boots and runs the reader UI.
   (`-DMURPHY_BRINGUP_LOG=1` adds a 5 s serial heartbeat used for verification.)
4. **I2C map probe** ([probes/i2c-scan/](../probes/i2c-scan/)) — live hardware confirmation:

   | Device | Addr | Result |
   |---|---|---|
   | ES8388 codec | **0x10** | ACKs — CE strap = 0x10 confirmed (freeink-sdk config correct) |
   | CHSC6x-class touch | 0x2e | ACKs |
   | RX8010SJ RTC | 0x32 | ACKs, seconds register ticking — RTC alive |
   | AHT30 temp/humidity | 0x38 | ACKs, status 0x18 (calibrated) |

   **New findings beyond the schematic:**
   - **GPIO43 gates the entire I2C bus**, not just the codec — bus scans empty with it low.
   - **GPIO45 (touch power) HIGH removes both touch AND codec** from the bus (CH442E analog
     switch). Keep it LOW for touch + codec access.
   - Repeated-start register reads NACK on ES8388/touch with the Arduino `Wire`
     `endTransmission(false)` idiom; plain address ACK works. Use stop-separated reads.

## The USB reset trap (important for anyone flashing an M3)

After any esptool/PlatformIO session over the native USB-Serial/JTAG, the chip **keeps
re-entering ROM download mode on every reset** ("`waiting for download`", strap `0x23`) — the
DTR/RTS handling of Linux cdc-acm + esptool leaves the download strap asserted at the moment
of reset (arduino-esp32 issue #6762 family). Software resets (JTAG `reset run`) re-use the
stale strap sample, so they don't help.

**Working recipe** (no physical touch needed):
```bash
# after flashing, trigger a TRUE reset via JTAG RTC-WDT (straps re-sample cleanly):
OO=~/.platformio/packages/tool-openocd-esp32
$OO/bin/openocd -s $OO/share/openocd/scripts -f board/esp32s3-builtin.cfg -c \
  "init; sleep 500; targets esp32s3.cpu0; halt; sleep 200; \
   write_memory 0x600080B0 32 0x50D83AA1; write_memory 0x6000809C 32 2000; \
   write_memory 0x60008098 32 [expr {(1<<31)|(5<<28)|(1<<8)|2}]; \
   write_memory 0x600080B0 32 0; resume; sleep 1200; shutdown"
```
Physical unplug/replug does the same. Holding the bottom button (GPIO0) at reset enters the
bootloader manually — that's the recovery path, never a brick.

Serial monitoring: plain `serial.Serial('/dev/ttyACM0', 115200)` open is harmless while the
app runs; do **not** toggle DTR/RTS (that's what re-enters download). Note the USB device
re-enumerates (new /dev node instance) after a WDT reset.

JTAG access needs the usb node writable (`303a:1001`); on this box that's done per-plug via
docker (`grant your user access to the USB node (a udev rule is the correct fix)`) — a udev rule would be the permanent fix (needs sudo).
